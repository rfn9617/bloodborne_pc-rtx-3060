# Windows: i7-11800H, 32 ГБ RAM, RTX 3060 6 ГБ

Профиль: Full HD, DLSS Quality (сцена 1280×720), лимит 72 FPS, Mailbox,
один кадр вперёд, векторы движения объектов включены. Модель DLSS K сохранена
по выбору пользователя: на его системе достигаются 72 FPS с более качественной картинкой.
144 FPS не предлагается: выше примерно 120 FPS проект предупреждает о замедлении
движения игры. Стабильность 72 FPS зависит от локации, питания и температур ноутбука.

Профиль отключает собственный AA игры поверх DLSS и диагностику GPU.
DoF, motion blur, chromatic aberration, SSAO и динамические тени остаются
настройками пользователя. LOD моделей −2
сохраняет детализацию, но не меняет дальность отсечения/загрузки объектов.
Уровень текстур решёток `alpha_detail=2` работает без перезапуска. Он влияет на
текстуры с альфа-вырезами, а не на загрузку отсутствующей геометрии, и может усилить
мерцание. Дверь, появляющаяся целиком на определённой дистанции, требует отдельной
проверки отсечения/стриминга игры; этот профиль не обещает исправить её.

Настройки служат значениями по умолчанию. Существующие сохранения, папки игры,
моды и настройки сохраняются. Для применения профиля к уже настроенной копии:
**Дополнительно → Применить профиль RTX 3060 6 ГБ (72 FPS)**, затем перезапустить игру.
Сборка не устанавливает обычные обновления upstream поверх локальных исправлений.

## Сборка в Windows

В MSYS2 CLANG64 установите зависимости по `packaging/windows/README.md`, затем:

```bash
git submodule update --init --recursive
BB_LTO=OFF bash build.sh
DLSS_SDK_ROOT=F:/sdk/DLSS bash packaging/windows/build_dlss.sh
bash packaging/windows/package.sh --profile rtx3060-6gb --minimal
```

Для моста DLSS нужны MSVC 2022 и официальный NVIDIA DLSS SDK. Упаковка завершится
ошибкой, если отсутствуют мост, runtime DLSS или его лицензия. Результат:
`dist/bbport-windows-rtx3060-6gb.zip`. В нём нет Linux-лаунчера, инструментов
разработки и ассетов FSR 4. FSR 3.1 остаётся для случая недоступности DLSS.
Никакие игровые файлы не включены; нужен собственный decrypted dump версии 1.09.

## Кеш и проверка на ПК

Исправлен потерянный при загрузке дискового кеша признак alpha discard.
Версия метаданных изменена; старые записи не используются. Первый проход после
обновления может заново компилировать шейдеры/пайплайны. Повторный запуск должен
снова выводить `Texture detail: alpha_detail=2` с отрицательным bias, когда рисуется
материал с вырезами. Не очищайте кеш перед каждым запуском.

Профиль сохраняет `BB_GC_IDLE_SECONDS=20`, чтобы не увеличивать повторные загрузки
текстур при возвращении в локацию. Давление памяти
по-прежнему определяется бюджетом драйвера (85%/93%). Данные, существующие только
на GPU, не удаляются вслепую. Кеш может оставаться выше первоначальных 3,5 ГБ;
важно, чтобы рост прекратился и очистка работала, а не точное совпадение чисел.
Уменьшенные копии буферов сцены теперь также освобождаются после удаления исходного
изображения; до исправления они удерживались до смены разрешения. Освобождение
отложено до окончания работы GPU с ними. Также исправлен учёт возраста текстур,
когда во время загрузки или паузы пропущено несколько секунд.

Для проверки включите статистику кадров, а профиль GPU включайте только для
короткого сравнения. Проверьте одинаковый маршрут **Ярнам → Сон охотника → Ярнам**
не менее трёх раз и постойте 10 секунд после каждой загрузки. Сравните VRAM,
`images evicted`, `written back`, p99 времени кадра и худший кадр. Сравнение
`BB_GC_IDLE_SECONDS=20` и `5` допустимо только как отдельный эксперимент: ранняя
выгрузка может усилить повторные загрузки. Если рост продолжается каждый круг,
нужен полный лог от запуска. Исходные данные обычных текстур остаются в RAM игры;
удаление копии из VRAM не требует повторного чтения этих данных с диска.

С учётом 32 ГБ RAM профиль увеличивает удержание буферов загрузки в системной
памяти: `BB_STAGING_KEEP_MB=1024`, предварительная подготовка
`BB_STAGING_PREWARM_MB=256`. Это на каждый пул: базовый запас двух пулов достигает
2 ГБ RAM, из которых суммарно 512 МБ подготавливаются при запуске. Временный расход
во время активной загрузки может быть выше; это не лимит RAM всего процесса.
Это переиспользуемые буферы передачи данных, а не дополнительные копии всех
текстур. После исправления этот лимит больше не удерживает такой же объём
временных буферов в VRAM. Начальная загрузка может стать немного дольше; ожидаемое
снижение задержек выделения памяти при стриминге нужно измерить на ПК.

Для решётки сравните `alpha_detail=0` и `3` с одной камеры и на одной дистанции
у двери справа от первого фонаря Центрального Ярнама: исчезают только тонкие
прутья, сама дверь остаётся. Используйте LOD −2 и повторите проверку после
перезапуска (кеш уже заполнен). Не меняйте одновременно DLSS-пресет,
LOD и alpha detail. Замер производительности делайте после прогрева кеша и с
отключённым профилем GPU. В облачной Linux-среде Windows-исполняемые файлы,
изображение и производительность на RTX 3060 не проверены.
